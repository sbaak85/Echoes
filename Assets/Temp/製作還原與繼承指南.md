目標是在伊薩卡號檢查曲速引擎時，讓玩家操作「4 個插槽、3 張匯流排卡」完成簡單工程解謎。目前交付的是可玩的獨立瀏覽器預覽；這個敘事情境是用途背景，**尚無正式章節事件掛勾**。

原始預覽來自本對話附掛的 `world-item-icon-preview/EchoesBeyond` Worktree，位於它的 `output/`；不是主專案已整合的功能。本包把兩個資料夾完整複製到 `previews/`，另加獨立啟動與驗證工具。**兩份原始預覽程式與資源保持原樣**；原資料夾的 README、server 及提示詞內仍可能保留當時的路徑／說明，搬家後以本文件與根目錄 README 為準。

沒有包含：主遊戲、船艙 Three.js 模型、ChapterScriptEditor、角色資料庫、任務／Item 資料、主遊戲存檔、Git 資料夾、node_modules、Codex 私有環境與聊天工具狀態。這不是聊天紀錄的完整備份，而是可執行的遊戲原始檔與接續製作說明。

## 2. 家中電腦還原

### Windows

1. 把 ZIP 複製回家，完整解壓到新的資料夾，例如 `D:\GamePrototypes\IthacaBusCard`。不需要復原公司的使用者名稱、C 槽路徑或 Worktree 結構。
2. 在終端機執行 `node --version`。本次驗證使用 v24.19.0；未附執行檔。沒有 Node 時，從 [官方網站](https://nodejs.org/) 安裝。也可從官方 Windows 可攜式版本取出 `node.exe` 及其授權檔放進本包 `runtime/`。
3. 初次接手先執行 `verify.cmd`，應顯示所有列入基準的檔案相符。這個工具只讀取，不會替你還原或刪除修改。
4. 雙擊 `start.cmd`。它以自身位置為根目錄啟動伺服器，開啟預設瀏覽器的直式版本。
5. 想看橫式時，既有伺服器的 `/landscape/` 就能用，不必重開一個相同埠的伺服器。
6. 雙擊 `test.cmd` 跑兩版既有測試。測試通過後再開始改；實際互動仍需在瀏覽器確認。

預設埠 3070。占用時使用 `start.cmd --port 3071` 或 `start.cmd --port 0`；後者由作業系統挑埠，以命令視窗印出的網址為準。`start.cmd --no-open` 只啟動、不自動開系統瀏覽器。

伺服器只聽 `127.0.0.1`，不對外公開；網頁、圖片、程式和音效生成全在本機。執行遊戲不需要網路。不能直接用 `file://` 開 `index.html` 代替 HTTP，因為程式使用 ES modules。

## 3. 玩法與資料規則

### 三張卡

| 卡片 | 名稱 | 導通距離 | 電流顏色 |
| --- | --- | --- | --- |
| A | 短距匯流排 | 1 節 | 琥珀 `#f3bc68` |
| B | 中距匯流排 | 2 節 | 青綠 `#5fdbc8` |
| C | 長距匯流排 | 3 節 | 淡紫 `#b9a0ff` |

每張卡只有一張，不允許同時插入多槽；一槽只能有一張卡。入口由插槽決定，終點 = 入口編號 + 卡片節數。插拔次數目前只是計數，沒有時間限制、扣分或失敗懲罰。

### 四個插槽與完整路線表

| 插槽 | 程式索引 | 入口 | A 卡終點 | B 卡終點 | C 卡終點 |
| --- | --- | --- | --- | --- | --- |
| S01 | 0 | 00 | 01 | 02 | 03 |
| S02 | 1 | 03 | 04 | 05 | 06 |
| S03 | 2 | 01 | 02 | 03 | 04 |
| S04 | 3 | 04 | 05 | 06 | 07 |

接點意義：00 電源；01、03、04 轉接；02、05、07 盲端；06 引擎核心。

串接只看相同接點編號，不看管道畫面是否交叉。終端的左右位置純粹是視覺配置，不影響規則。盲端沒有可繼續串接的對應插槽入口，但仍有實際管線可抵達。

### 成功條件與三組解法

從 00 出發，依「目前終點 = 下一段入口」追蹤，三張卡都要包含在同一條三段鏈上，最後到達 06。只到核心但不足三段不算完成；局部通電也不算。

24 種不同卡片配置中有 3 組有效解法（空槽以 — 表示）：

| S01 | S02 | S03 | S04 | 串接順序 |
| --- | --- | --- | --- | --- |
| A | C | B | — | 00 → 01 → 03 → 06 |
| A | — | C | B | 00 → 01 → 04 → 06 |
| C | A | — | B | 00 → 03 → 04 → 06 |

模型的 `evaluate()` 回傳邏輯上的完成；畫面還要等待三段動畫充滿並穩定 **0.65 秒**才顯示「導通完成」。完成後仍可拔卡，立即中斷完成狀態，並觀看電流收回。

## 4. 插拔、拖曳、交換與輸入

- 卡架 → 空槽：按住拖曳，放開插入。
- 已插入的卡在原槽內小幅拖動：仍保持插入；跨出槽邊界後才拔出並開始收回電流。
- 已插入的卡 → 空槽：拔出後換槽插入。
- 已插入的卡 → 另一張已插入卡：放開時兩張卡交換；兩條新路線重新充能。
- 已插入的卡 → 插槽外：回卡架，保持拔除。
- **卡架的卡 → 已占用插槽：不交換，退回卡架**。交換功能要求被拖的是原本已插入的卡。
- 點一下卡架卡片，再點空槽，也可以插入；點已占用槽可拔除並選取該卡。
- Esc、頁面失焦、切換分頁、pointercancel、失去 pointer capture 或改由其他輸入方式接管時，會取消未完成拖曳並恢復原卡位；不讓拖曳結束多觸發一次點擊。
- 「重新測試」清空配置、計數與提示階段，既有能量沿原路收回。
- 音效預設關，可開啟；透過 Web Audio 合成，不依賴外部音檔。

拖曳開始門檻：滑鼠位移 7 px，觸控／筆 11 px；離開原槽的判定額外留 4 px 容差。對應程式為 `drag.mjs` 的 `moveDrag()`／`dropIntent()`。

插拔次數依物理動作計算：一次卡架插入 +1、拔出 +1、換空槽合計 +2、已插卡交換合計 +4（兩張卡各拔／插一次）。取消拖曳會恢復先前計數，不能把計數當成「手勢數」。

### 鍵盤、手把與觸控

| 輸入 | 現有操作 |
| --- | --- |
| 鍵盤 | 方向鍵或 Tab／Shift+Tab 移動，Enter／空白確認，Esc 取消 |
| 手把 | 左搖桿／方向鍵移動，A 確認，B 取消 |
| 滑鼠 | 拖曳插拔交換，也能點選操作 |
| 觸控／筆 | Pointer Events 拖曳與點選路徑 |

手把方向門檻 0.55，首次長按重複間隔 370 ms，後續 165 ms；按鍵使用邊緣觸發。失焦或裝置斷線後須回到中立狀態再重新啟用。

**UI 修改適用 [browser-ui-focus-visuals/SKILL.md](../rules/browser-ui-focus-visuals/SKILL.md)。** 隱藏瀏覽器原生焦點外框，但保留語意按鈕與可操作性；`data-nav` 是刻意的遊戲選取框。滑鼠、鍵盤方向、手把與觸控採單一輸入擁有者。此獨立預覽沒有右搖桿虛擬游標；不能把技能的一般要求誤寫成已實作功能。整合主遊戲時，須使用主遊戲既有游標與阻擋 UI 機制。

## 5. 電流視覺與狀態

- `app.mjs` 的 `pathData()` 依插槽入口與卡片距離產生 SVG 路徑。
- 每次插卡建立路徑外殼、管道、發光、填充、前端光點與 4 顆流動粒子。
- 充能使用 `stroke-dasharray` 沿路徑增加可見長度；標準時間為 `1.15 + 路徑長度 / 2500` 秒。
- 拔卡由當前進度反向收回，參數時間 0.85 秒；從半程拔出時不會先跳到終點。
- 單幀 dt 上限 0.05 秒，避免切回分頁後大幅跳動；頁面在背景時動畫可能被瀏覽器暫停／降頻。
- 每張已插卡都會顯示自己的局部電流，不要求它已接到主電源。右側串聯進度只計算從 00 能連到且充能完成的連續段。
- 幾何上相交不導通；目前沒有額外的橋接線、路口開關或交叉節點。
- 插槽交換時舊能量可仍在退回、新能量開始前進，這是現有視覺行為。

## 6. 最新直式視覺規格（避免接手時改回去）

主板 SVG 的 viewBox 為 `0 0 490 430`。最新直式 `app.mjs` 使用：

```js
const nodeX = node => [108, 140, 116, 146, 120, 152, 110, 136][node];
const labelX = 71;
const nodeY = node => 45 + node * 50;
const laneX = index => 190 + index * 76;
```

1. 00–07 的**終端槽位本體**左右錯開，Y 仍按順序往下。
2. 數字與說明文字都固定 `x = 71`、靠右對齊，不隨槽位左右偏移。
3. 所有動態管線以 `nodeX(from)`／`nodeX(to)` 接到實際槽位中心。
4. 每路原有 `lane-base` 延伸至 +3 的終點；新增 span 1、2 的 `lane-branch` 水平分支，總共 8 條，讓包括 02／05 的接點都不再孤立。
5. 細線樣式：`stroke: #7c9ca3; stroke-width: 1.2; opacity: .3; fill: none`。它們是靜態布線，不能誤計為額外完成路線。
6. 數字、規格、插槽、Hover、拖曳目標、電流都由 HTML／CSS／SVG 疊加；不要烘焙進主板圖片。
7. 直式卡片是重新構圖的資源：辨識牌在上、能源核心在中、六片接點在下；不是把橫式圖整張旋轉 90 度。

圖片由本對話先前的內建 image_gen 生成。遊戲使用的是包內 PNG，執行時不會再呼叫生成服務。提示詞只用於接續創作；再次生成不保證產出同一張圖，精確還原必須保留 PNG。

提示詞 JSON 的 `path` 是當時參考圖在原電腦的來源位置，**不參與執行**。搬家後，科幻版提示詞的參考圖對應本包的 `motherboard.png`／`bus-module.png`；直式提示詞的參考圖對應橫式的 `motherboard-v2.png`／`bus-module-v2.png`。不要為了這些歷史欄位重建原電腦絕對路徑。

卡片字母、距離、顏色、插入狀態都是程式疊加。音效由 `tone()` 生成。字型使用系統字型，未附商用字型檔。PNG 尺寸、位元組與 SHA-256 可查 `manifest.json`。

## 8. 程式架構與修改入口

每版都包含下列檔案：

| 檔案 | 職責 |
| --- | --- |
| `index.html` | 主板、診斷區、卡架、SVG 容器與濾鏡；引入 CSS／模組 |
| `model.mjs` | 卡片／插槽定義、插入／移除／交換、路線計算、完成判定、充能進度 |
| `app.mjs` | 遊戲狀態、畫面生成、事件串接、提示、音效、電流動畫、完成顯示 |
| `drag.mjs` | Pointer Events、門檻、移出判定、交換意圖、拖曳浮卡、取消與清理 |
| `input.mjs` | 輸入擁有者、鍵盤／手把導航與確認取消、裝置接管 |
| `style.css` | 基本排版、字型、節點與路線、響應式 UI |
| `drag.css` | 拖曳浮卡與目標狀態、插入／返回動畫 |
| `hardware.css` | 主板／卡片材質、硬體外觀、科幻 v2 覆寫 |
| `portrait.css` | 直式專屬排版、直向卡片與細淡分支；只有直式有此檔 |
| `*.test.mjs` | Node 內建 test runner 的既有檢查 |
| `server.mjs` | 原 Worktree 的單版啟動入口，仍可獨立使用 |

根目錄新增的 `server.mjs` 同時提供 `/portrait/` 與 `/landscape/`，沒有改遊戲內部模組。路徑從 `import.meta.url` 解出；不用依賴命令啟動位置。它採白名單，只對本機供應預覽需要的網頁／程式／圖片，不供應整個磁碟或文件。

封裝時兩版 `model.mjs`、`drag.mjs`、`input.mjs` 相同，但它們是兩份檔案，不是共享 import。兩版 `app.mjs`、CSS 與美術有差異。這次為維持基準，沒有抽共通架構；未來抽取時請先保留可比較的備份。

## 9. 驗證、故障排除與已知邊界

現有每版 14 個測試，兩版合計 28 個。涵蓋全部 24 種卡位的三組解法、移除造成中斷、重複卡與占位防護、充能反向、已插卡互換、拖曳門檻／回槽／取消，以及部分模擬輸入交接。`input.test.mjs` 和 `drag-lifecycle.test.mjs` 使用模擬 DOM／事件；**不是實體手把或手機驗收**。

測試命令與最新封裝檢查結果見 [驗證紀錄](驗證紀錄.md)。瀏覽器驗收至少包括：

1. 空板所有文字對齊，槽位錯開，盲端細線可見。
2. A → S01，C → S03，B → S04，看到 00 → 01 → 04 → 06 完成。
3. 任一已插入卡拖到其他已插卡位置，兩卡交換，不遺失／複製。
4. 拖出插槽後放開，電流收回；取消拖曳可回原位。
5. 縮小視窗時能操作；原生焦點框不出現，但鍵盤選取可見。

| 狀況 | 排查 |
| --- | --- |
| 找不到 node | 安裝 Node、重開終端，或依 README 放入 `runtime/node.exe` |
| 開不了 3070 | 看命令視窗；換 `--port 3071` 或 `--port 0`，不要直接結束不明程式 |
| 圖片不見／模組失敗 | 完整解壓、用 HTTP 網址、執行 verify；確認保留 assets 相對路徑 |
| 修改看不到 | 重新整理；伺服器設 no-store，但不會自動推播更新 |
| verify 顯示 CHANGED | 若剛改過屬正常；它比較原封裝基準。先看 diff，不要自動覆蓋 |
| 重新整理後配置清空 | 現有設計只存記憶體，無 localStorage、存檔或回放 |
| 音效沒聲音 | 先按音效開關；瀏覽器須有使用者手勢，且可能受系統靜音影響 |

目前沒有：隨機關卡、難度產生器、計時失敗、遊戲劇情回呼、獎勵／道具消耗、儲存進度、完整掛載／卸載 API。頁面透過全域 DOM、document 事件與持續 requestAnimationFrame 運作；不能直接當成已能安全反覆開關的主遊戲元件。

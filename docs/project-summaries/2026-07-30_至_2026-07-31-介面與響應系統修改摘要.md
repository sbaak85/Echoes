# Echoes 介面與響應系統修改摘要

- 整理日期：2026-07-31（Asia/Taipei）
- 涵蓋期間：2026-07-30 至 2026-07-31
- 專案路徑：`D:\Codex\Echoes`
- 遠端專案：`https://github.com/sbaak85/Echoes`

## 一、這一階段的製作方向

本階段主要將原本偏測試用途的遊戲介面，逐步整理成可正式擴充的遊戲 UI 系統，並補上 PC、手把與行動裝置之間的響應行為。修改重點集中在 Options、指南針、生存狀態、任務提示、快捷工具列、背包介面、全螢幕舞台及輸入模式整合。

核心原則如下：

1. 一般 PC 視窗使用最大寬度 `1800px`、比例 `16:9` 的遊戲舞台。
2. 未全螢幕時，所有 UI 以遊戲舞台四邊為響應基準，不直接貼齊瀏覽器視窗。
3. 進入 F11 或 Fullscreen API 全螢幕後，舞台解除 `1800px` 限制，擴展至螢幕四邊；上、下、左、右 UI 同步貼齊全螢幕舞台。
4. 行動裝置仍保留直式與橫式響應，不因 PC 的 1800 舞台規則而被鎖成固定橫版。
5. 滑鼠、虛擬游標、鍵盤、手把及觸控操作共用同一套 UI 互動狀態，避免輸入指令穿透到場景尋路。

## 二、Options 選項視窗

- 將原本的 Debug 視窗整理成正式的 Options 選項視窗。
- 入口改為遊戲畫面左下角的齒輪按鈕，手把 `START` 仍可開關。
- 使用畫面、音效、操作等頁籤分類。
- 選項視窗固定為螢幕高度約 60%，內容過多時使用垂直捲動。
- 手把以 `LB`、`RB` 切換頁籤；上下鍵只在目前頁籤項目中循環。
- 對話框文字大小提供小、中、大；PC 預設小，行動裝置預設大。
- 操作頁加入「開啟虛擬游標控制」開關。

## 三、輸入提示與行動裝置控制

- 移除原本整排 WASD、手把連線與操作說明底框。
- 手把連線文字移至左上角場景資訊區。
- WASD 圖示改為偵測鍵盤輸入時才顯示，並同步亮起實際按鍵。
- 行動裝置下半部畫面支援全區域 Hold 觸控虛擬搖桿：
  - 觸碰時在起點生成半透明圓形搖桿。
  - 拖曳時箭頭依 360 度方向旋轉。
  - 放開後隱藏。
- 行動裝置上半部仍保留單點尋路及互動，不與下半部虛擬搖桿混用。
- 滑鼠與手把虛擬游標維持最高 UI 圖層，指向 UI 時不得繼續觸發地圖尋路。

## 四、角色狀態與指南針

- 將原本右下角的角色方位資訊移除。
- `FACING`、`MOVING`、`INTERACTIVE` 等狀態文字改為畫面下方置中顯示。
- 新增畫面上方中央的平面指向指南針：
  - 正中央為角色目前面向，字級最大。
  - `N`、`S`、`E`、`W` 大於斜向方位文字。
  - 方位之間加入三道次刻度線。
  - 移除中央多餘的直桿及圓點。

## 五、生存狀態與任務提示 UI

### 生存狀態

- 左上角加入 Day、時間、體力、飢餓、口渴、精神量表。
- 目前先完成 UI 與資料結構，實際下降、補充及睡眠恢復規則留待後續討論。
- 行動裝置及窄畫面使用迷你狀態表，點擊後可向右下展開完整版。
- PC 同樣可使用迷你／展開操作。

### 任務提示

- 右上角加入主線任務標題、目標及進度 UI。
- 可點擊三角形收折，PC 收折後保留一行任務標題與進度。
- 行動裝置預設收折，並使用更短、更小的行動版摘要樣式。
- 修正任務面板，使其以遊戲舞台右上角為定位基準。

## 六、快捷工具列與手把操作

- 左下角加入 7 格背包快捷工具列。
- 支援數字鍵與滑鼠點擊，使用時播放選取／按壓回饋。
- 手把遊玩時取消十字鍵直接移動角色：
  - 十字鍵左右選擇快捷格。
  - 十字鍵上下暫不指定功能。
  - `Y` 使用目前快捷格物品。
- 游標進入快捷工具列的整體範圍後保持手指游標，不因格子縫隙而跳回一般游標。
- 虛擬游標按下確認鍵時優先操作 UI，不得穿透成角色尋路。

## 七、背包介面

- 手把 `B` 與鍵盤 `Tab` 可開關背包。
- 背包開啟後停止場景操作，並以約 45% 黑色半透明遮罩壓暗遊戲畫面。
- Day／時間及原本左下角快捷工具列沿用遊戲外層元件，開啟背包時提升至遮罩上方，不建立重複介面。
- 背包主要區塊包含：
  - 生存背包與負重、分類統計。
  - 選中道具預覽、說明及使用／查看／標記／丟棄操作。
  - 全部、資源、道具、任務道具、主線道具分類。
  - 排序、篩選與搜尋欄位。
  - 4 × 4 共 16 格道具清單及翻頁控制。
- 生存背包、選中道具與 16 格資源區已重新緊縮、靠攏並對齊。
- 放大資源格文字、分類標題、統計資訊及底部翻頁箭頭／頁碼。
- 手把操作採「最後一次操作來源」：
  - 最後使用虛擬游標時，`A` 操作游標指向的道具。
  - 最後使用十字鍵時，`A` 操作十字鍵框選的道具。
- 修正手把 `B` 被瀏覽器誤判為右鍵的問題。
- 修正背包開啟瞬間右上角關閉按鈕跳位的問題。

## 八、遊戲啟動與全螢幕舞台

- 遊戲啟動加入 1 秒黑畫面 Fade In。
- 舞台外側使用地圖模糊、壓暗背景填補寬螢幕空間。
- 行動裝置右下角加入小型全螢幕按鈕，使用 Fullscreen API 展開。
- PC 支援瀏覽器 F11 全螢幕偵測。

### 全螢幕修正經過

1. 第一版將 UI 直接依瀏覽器視窗定位，造成尚未 F11 時就貼到螢幕四角，且舞台高度提前擴展。
2. 第二版把全螢幕判定限制得過嚴，部分 Windows／Chrome 的 F11 邊框差超過 12px，導致全螢幕沒有擴展。
3. 目前版本放寬工具列消失判定，同時為全螢幕舞台明確設定四邊 `inset: 0`、`100vw × 100dvh`、移除最大寬高與置中位移限制。

目前預期結果：

- 一般 PC：最大 `1800px`、16:9、置中，UI 貼齊遊戲舞台。
- PC F11：舞台擴展至螢幕頂底及左右，UI 貼齊全螢幕舞台四邊。
- 行動裝置：依實際直式／橫式螢幕填滿，不受 PC 1800 舞台規則限制。

## 十、已知問題與注意事項

- F11 是瀏覽器層級全螢幕，沒有標準網頁事件可直接判斷，目前以視窗與螢幕尺寸、瀏覽器工具列高度差推定；不同瀏覽器仍需實機確認。
- 全螢幕下地圖 Canvas 會依舞台尺寸顯示，之後若加入不同解析度地圖，需再明確定義 cover、contain 或相機視野擴展規則。
- 生存數值與任務資料目前仍以 UI 架構及示範資料為主，尚未完成正式遊戲規則與存檔串接。
- 背包道具目前為示範資料，使用、消耗、重量、任務連動及持久化仍待實作。
- `public/characters/walk/Test/` 為本機未追蹤測試素材，本次摘要提交不包含該資料夾。

## 十一、建議下一步

1. 分別用一般視窗、最大化視窗與 F11 實測 PC 舞台及四角 UI 定位。
2. 以手機直式、手機橫式及平板尺寸測試迷你生存表、任務收折、虛擬搖桿和全螢幕按鈕。
3. 確定全螢幕顯示規格後，將舞台尺寸判定整理成單一共用函式，降低後續 UI 響應規則互相覆蓋的風險。
4. 討論並實作生存值下降／恢復公式、任務資料格式與背包正式道具資料模型。

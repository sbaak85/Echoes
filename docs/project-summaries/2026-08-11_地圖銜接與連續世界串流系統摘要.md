# Echoes 地圖銜接與連續世界串流系統摘要

日期：2026-08-11  
目前範圍：`Scene_2`＋`Scene_3` 第一版連續世界串流

## 一、系統定位

目前版本已從原本「進出口觸發後直接切換場景」改為可玩的雙場景平滑換場 MVP。

遊戲會把 Scene_2 與 Scene_3 放進同一套世界座標，預先解碼相鄰地圖圖片；玩家進入場景連接區時，不重建整個遊戲畫面、輸入與音效系統，而是讓角色及攝影機沿世界座標平滑移動到相鄰場景，完成後再切換該場景的 NavMesh、Collision、互動區、劇情區、ItemPoint 與小地圖資料。

視覺上已接近「攝影機滑到隔壁地圖」，但底層仍屬於經過平滑包裝的 Portal／Teleport，還不是角色在同一份大型世界資料中真正跨越場景邊界。

## 二、目前已完成

### 1. 場景登錄與世界座標

- 已登錄 Scene_2、Scene_3 與各自的場景 JSON。
- 場景資料已有 `worldLayout`，可描述場景在連續世界中的 X、Y 與 Layer。
- Scene_2 與 Scene_3 已配置相鄰位置及雙向 Connection／Entry Point。

### 2. 相鄰地圖預載

- 進入目前場景時，會提前載入並解碼相鄰場景圖片。
- 切換時不需要臨時才開始讀取完整背景圖。
- 同一 Layer 的場景背景可依世界座標一起繪製。

### 3. 常駐遊戲迴圈

- 換場時不會重新建立主要 Canvas、遊戲迴圈、輸入系統與音效系統。
- 玩家、攝影機與換場流程由同一套常駐 Runtime 管理。
- 減少原本場景重建造成的明顯停頓。

### 4. 平滑場景過渡

- 進入 Connection 後，角色與攝影機會由來源位置平滑插值至目標 Entry Point。
- 過渡完成後才正式啟用目標場景的遊戲資料。
- 目前支援 Scene_2 ↔ Scene_3 雙向移動。

### 5. 抵達鎖定

- 抵達新場景後會暫時鎖住剛使用過的連接點。
- 玩家必須離開連接範圍並移動一段安全距離後，該出口才重新生效。
- 用來避免角色抵達後立刻再次觸發，造成來回彈跳。

### 6. 場景 Runtime 切換

完成過渡後會切換至目標場景的：

- NavMesh
- Collision
- 互動多邊形
- 強制引導線
- 劇情觸發區
- ItemPoint
- 小地圖輪廓資料

## 四、主要不足與風險

### 1. 仍是固定 Entry Point 傳送

角色目前不是保留「穿越接縫時所在的位置」進入下一張地圖，而是移動到預先指定的 Entry Point。

尚未保留：

- 穿越出口時在出口上的相對位置
- 原本的移動方向
- 原本的移動慣性／輸入狀態
- 兩張地圖接縫的精準對位

因此視覺雖然平滑，仍可能感覺角色被吸到固定落點。

### 2. 只有背景是連續的

相鄰場景目前主要提前呈現背景；目標場景的以下內容要等正式切換後才啟用：

- 場上 Item
- 互動提示點與名稱
- NPC／未來角色
- 特效與環境事件
- Collision 與互動判定

因此靠近接縫時，遠處物件仍可能突然出現。

### 3. 沒有跨場景尋路與碰撞

- 點擊移動尚不能規劃 Scene_3 → Scene_2 的完整跨場景路徑。
- 過渡插值期間不是由 NavMesh 尋路驅動。
- 過渡路線不會完整繞過跨場景障礙。
- 相鄰場景 Collision 尚未共同參與同一套即時判定。

### 4. 沒有儲存玩家所在場景

目前重新整理或重新開啟後，仍可能回到預設 Scene_3 與出生點。

尚需儲存：

- Scene ID
- 玩家局部／世界座標
- 面向
- 必要時的最後安全 NavMesh 位置

### 5. 場景內物件 ID 可能互相衝突

部分互動次數、ItemPoint 狀態目前仍可能只使用物件 ID 紀錄。如果不同場景出現相同 ID，可能共用到同一份進度。

建議統一改為：

`SceneId:ObjectId`

例如：

`Scene_3:interaction-001`

### 6. 場景清單仍為程式內固定登錄

目前新增 Scene_4 後，遊戲端不一定會自動知道新場景存在，仍需要修改程式內的場景 Registry。

MapEditor 尚未自動輸出遊戲可直接讀取的 Scene Manifest／Index。

### 7. 預載不等於保證完成

目前會提早開始圖片載入與解碼，但觸發換場時未必會等待所有必要資源確實 Ready。

在裝置較慢、網路較慢或圖片較大時，仍可能發生瞬間停頓。

### 8. 場景數量增加後的效能問題

目前會繪製同 Layer 的已登錄背景。當地圖增加很多張後，若沒有可視範圍裁切與快取回收，會增加：

- 每幀繪製成本
- 記憶體占用
- 圖片解碼與保留成本

### 9. 小地圖仍是單場景模式

- 小地圖目前在場景切換後才換成新場景輪廓。
- 尚未把相鄰場景輪廓依世界位置拼成連續地圖。
- 尚未呈現跨場景的出口、任務點與已探索範圍。

### 10. 文件與自動驗證不足

- `docs/scene-format.md` 的部分說明已落後於目前實作。
- 尚未建立 Connection 與 Entry Point 的雙向連結驗證。
- 尚未自動檢查 Scene ID、Entry ID、目標 Scene 與世界位置是否有效。
- 尚未完成反覆往返、行動裝置、手把、不同畫面比例及重新載入的完整測試。

## 五、MapEditor 已有欄位但遊戲端尚未完整支援

- `triggerMode = manual`：手動觸發出口尚未完整接入。
- `triggerMode = choice`：出口選擇介面尚未實作。
- `transitionMode = blackout`：黑幕換場模式尚未接入此系統。
- `transferMode = pathfind`：由尋路完成跨場景尚未實作。
- `cameraFocus = sceneRoot`：攝影機焦點選項尚未完整生效。
- 不同 Layer 的樓層／室內外關係尚未形成正式規則。
- SceneWillExit、SceneDidEnter、首次進入、再次進入等場景生命週期事件尚未建立。
- 劇情或任務直接指定跨場景移動尚未建立。
- 每個場景獨立的 BGM、環境音、天候與光照切換尚未接入。

## 六、建議下一版優先順序

### 第一優先：讓接縫真正自然

改用「出口座標映射」取代固定 Entry Point 吸附：

- 保留角色穿越出口時的相對位置。
- 保留面向與持續輸入方向。
- 依來源出口與目標入口的對應關係換算座標。
- 目標點不合法時才投影到最近安全 NavMesh。

### 第二優先：儲存與物件命名空間

- 儲存 Scene ID、玩家位置與面向。
- 互動區、ItemPoint、劇情區與其他場景物件狀態改用 `SceneId:ObjectId`。
- 對既有存檔做相容或遷移處理。

### 第三優先：場景自動登錄

- 由 MapEditor 或建置流程生成 Scene Manifest。
- 遊戲啟動時讀取 Manifest 建立 Registry。
- 新增地圖不再需要手動修改 `movement-lab.tsx`。

### 第四優先：完整 Runtime 預熱

除了圖片以外，提前準備相鄰場景的：

- NavMesh
- Collision
- 小地圖遮罩
- 互動區索引
- ItemPoint 狀態
- 必要音效與場景資源

### 第五優先：擴充成真正的連續世界

- 顯示相鄰場景的 Item、互動提示、NPC 與特效。
- 建立場景連接圖與跨場景尋路。
- 小地圖改為世界座標拼接。
- 只繪製攝影機附近場景，並建立快取容量與淘汰規則。

## 七、建議驗收項目

後續每次修改至少應檢查：

1. Scene_2 → Scene_3 可正常通過。
2. Scene_3 → Scene_2 可正常通過。
3. 連續往返五次不會反覆彈回或卡死。
4. 抵達後必須離開出口才可再次觸發。
5. 鍵盤、滑鼠、手把與行動裝置皆可換場。
6. 換場前後互動、Item、任務與劇情狀態不遺失。
7. 重新整理後回到正確場景與正確位置。
8. 直式、橫式、F11 全螢幕下攝影機與 UI 不跳位。
9. 目標場景資源未載入完成時有安全等待或降級處理。
10. 新增 Scene 後不修改遊戲主程式也能被自動發現。

## 八、目前結論

這一版已完成「雙場景可平滑往返、背景連續、遊戲迴圈不重建、抵達不反彈」的第一版骨架，足以繼續擴充地圖內容與驗證 Scene_2、Scene_3 的連接感。

下一個最有感的改善不是繼續拉長過場動畫，而是改成出口接縫座標映射，讓角色保留穿越位置與方向；接著補上存檔、場景物件命名空間及自動 Scene Manifest，系統才會從雙場景測試版成長為可長期擴充的正式地圖串流架構。

# 通訊陣列調頻小遊戲：Git 合併注意事項

日期：2026-08-13
專案：Echoes Beyond the Stars
檢查基準：本機 `main` 與 `origin/main` 目前同為 `654ae71`

## 結論

這次的「通訊陣列調頻」小遊戲在功能設計上是一個獨立模組，但為了讓主遊戲能開啟、關閉、顯示並使用手把操作，仍有修改主遊戲共用檔案。因此它不是完全可以整包複製、完全不碰主系統的獨立程式。

目前尚未提交的內容不會因為單純存在本機而影響公司電腦。若從家裡推送至遠端，而公司電腦沒有另外提交相同檔案，隔天通常只需正常 Pull；若公司電腦也修改或提交了相同的共用檔案，才需要 Merge 或 Rebase。

## 一、檔案分界

### 小遊戲專用檔案：衝突風險低

- `app/frequency-calibration-puzzle.ts`
  - 小遊戲規則、頻率計算、完成判定與事件資料。
- `app/frequency-calibration-puzzle.tsx`
  - 小遊戲視窗、WebGL／Canvas 波形、滑鼠及手把操作。
- `tests/frequency-calibration-puzzle.test.mjs`
  - 小遊戲規則測試。
- `public/ui/frequency-calibration/`
  - 本次只提交正式介面實際引用的 5 張圖片：
    - `coarse-dial-knob.png`
    - `current-band-frame.png`
    - `fine-slider-rail-retro.png`
    - `fine-slider-lever-retro.png`
    - `signal-meter-cell.png`
  - `*-source.png`、`reference-*.png`、`preview-*.png` 與已淘汰的舊滑桿圖只供生成、拆件或比對，不納入本次提交。

這些路徑只要公司電腦沒有另外建立同名檔案，Git 通常可直接加入，不會發生文字衝突。

### 主系統共用檔案：可能需要人工合併

- `app/movement-lab.tsx`
  - 匯入小遊戲元件。
  - 新增開啟／關閉狀態與預覽參數。
  - 串接手把方向鍵、A／B 鍵及控制權接管。
  - 在主遊戲畫面中掛載小遊戲視窗。
  - 這是最可能與公司電腦修改衝突的檔案。
- `app/globals.css`
  - 新增小遊戲版面、旋鈕、頻段框、訊號格、微調滑桿與響應式樣式。
  - 若公司電腦也在調整主遊戲 UI，此檔案很容易出現同檔不同區塊，甚至同一選擇器的邏輯衝突。
- `package.json`
  - 將小遊戲測試加入既有測試指令。
  - 通常可自動合併，但若兩台電腦同時修改同一條 scripts 字串，可能產生衝突。

### 本次小遊戲沒有直接修改的系統

- MapEditor 程式與場景編輯功能。
- `public/maps` 的 NavMesh、Collision、互動多邊形及場景資料。
- 任務、章節、對話、生存與道具資料管理器。
- 現有場景資料與任務流程資料。

因此，公司電腦若只修改 MapEditor 或地圖 JSON，與小遊戲本體直接發生 Git 文字衝突的機率較低；仍需留意公司端是否也動到 `movement-lab.tsx` 或 `globals.css`。

## 三、什麼情況不需要 Merge

符合以下情況時，公司電腦通常只需 Pull：

1. 家裡電腦先把小遊戲提交並 Push。
2. 公司電腦的分支沒有自己新增尚未推送的 Commit。
3. 公司電腦工作目錄乾淨，或只存在不會被 Pull 覆蓋的未追蹤檔案。

這時 Git 會進行 Fast-forward，不會建立 Merge Commit，也不需要人工處理衝突。

## 四、什麼情況需要 Merge

以下任一狀況成立，就可能需要 Merge：

1. 公司電腦已經對同一分支建立自己的 Commit，而家裡也已 Push 新 Commit。
2. 公司電腦修改了 `app/movement-lab.tsx`、`app/globals.css` 或 `package.json` 的相同位置。
3. 公司電腦也建立了 `app/frequency-calibration-puzzle.*` 或同名 UI 圖片。
4. 公司電腦有未提交修改，Pull 時會覆蓋同一檔案；Git 會先拒絕 Pull，要求處理本地異動。

注意：Git 沒顯示文字衝突，不代表一定沒有「邏輯衝突」。例如兩邊分別加入不同的手把輸入接管，雖然能自動合併，仍可能造成按鍵同時控制兩個視窗。

## 五、建議的安全合併流程

### 家裡電腦 Push 前

1. 確認狀態：

   ```powershell
   git status --short
   git fetch origin
   git log --oneline --left-right HEAD...origin/main
   ```

2. 只 Stage 小遊戲專用檔案與三個必要共用檔案：

   ```powershell
   git add app/frequency-calibration-puzzle.ts
   git add app/frequency-calibration-puzzle.tsx
   git add tests/frequency-calibration-puzzle.test.mjs
   git add public/ui/frequency-calibration/coarse-dial-knob.png
   git add public/ui/frequency-calibration/current-band-frame.png
   git add public/ui/frequency-calibration/fine-slider-rail-retro.png
   git add public/ui/frequency-calibration/fine-slider-lever-retro.png
   git add public/ui/frequency-calibration/signal-meter-cell.png
   git add app/movement-lab.tsx app/globals.css package.json
   ```

3. 再用 `git status --short` 檢查，避免把 Log、`tmp/`、影片或其他 UI 素材一起提交。

4. 最安全方式是先推到功能分支：

   ```powershell
   git switch -c feature/frequency-calibration
   git commit -m "加入通訊陣列調頻小遊戲"
   git push -u origin feature/frequency-calibration
   ```

   若確定遠端 `main` 沒有更新，也可以按既有流程提交到 `main`，但功能分支更方便隔天在公司電腦檢查與合併。

### 公司電腦開始工作前

1. 不要一開機就直接 Pull，先執行：

   ```powershell
   git status --short
   git branch --show-current
   git fetch origin
   git log --oneline --left-right --graph HEAD...origin/main
   ```

2. 如果有尚未提交的 MapEditor 或地圖修改，先提交到公司端功能分支保存，不要用 `git reset --hard` 清除：

   ```powershell
   git switch -c backup/company-mapeditor
   git add <確認過的公司端檔案>
   git commit -m "保存公司端 MapEditor 修改"
   ```

3. 再合併遠端最新版。若公司修改已在獨立分支，可先更新 `main`，再把公司分支合回；若公司已直接提交在 `main`，使用：

   ```powershell
   git merge origin/main
   ```

4. 發生衝突時逐檔處理，不要對整個檔案直接選「全部採用本機」或「全部採用遠端」。

## 六、三個共用檔案的人工合併重點

### `app/movement-lab.tsx`

合併時必須同時保留：

- 公司端新加入的主遊戲、MapEditor 資料或其他視窗接線。
- `FrequencyCalibrationPuzzle` 的 import。
- 小遊戲的開啟／關閉 state 與 ref。
- `frequencyCalibrationPreview=1` 預覽入口。
- 小遊戲開啟時的手把輸入接管。
- 元件的實際 render 區塊。

特別檢查所有視窗的輸入優先序，避免 Options、背包、電力分配與調頻小遊戲同時接收到 A／B 或方向鍵。

### `app/globals.css`

- 保留兩邊新增的完整 CSS 區塊。
- 檢查是否有重複 class、重複 media query 或後方樣式覆蓋前方樣式。
- 不要為了解一小段衝突而把整份 CSS 換成其中一台電腦的版本。
- 合併後要同時檢查 PC 與行動裝置尺寸。

### `package.json`

- 保留兩邊新增的 scripts 與相依套件。
- 確認逗號及 JSON 格式正確。
- `test:items` 若兩邊都有新增測試，必須把兩份測試路徑都保留。

## 七、圖片與二進位檔案的注意事項

PNG、MP4、EXE 等二進位檔無法像文字程式碼逐行 Merge。

- 若兩台電腦新增不同檔名，可直接並存。
- 若兩台電腦修改同一張同名圖片，只能人工選定正確版本，或先重新命名兩份再比較。
- 不要在沒有預覽的情況下直接選 ours／theirs。

## 八、合併後必做驗證

1. 檢查 Git：

   ```powershell
   git status --short
   git diff --check
   ```

2. 執行小遊戲規則測試：

   ```powershell
   node --experimental-strip-types --test tests/frequency-calibration-puzzle.test.mjs
   ```

3. 執行專案建置：

   ```powershell
   pnpm run build
   ```

4. 用瀏覽器驗證：

   - `?frequencyCalibrationPreview=1` 可正常開啟。
   - 粗調旋鈕、外圈刻度與數字同心對齊。
   - 「目前頻段」標題與數字置中。
   - 訊號強度格與微調頻率機械滑桿正常運作。
   - 滑鼠、鍵盤與手把皆可操作。
   - 關閉小遊戲後，角色與其他 UI 的控制權可正常恢復。
   - 電力分配小遊戲、Options、背包及主遊戲移動沒有回歸問題。

## 九、最重要的合併原則

- 先保存兩台電腦各自的成果，再合併，不要用破壞性指令消除其中一邊。
- 專用新檔通常直接保留；共用入口檔必須理解功能後人工合併。
- MapEditor 與地圖資料即使沒有直接衝突，也要確認沒有被小遊戲提交意外夾帶或覆蓋。
- 合併完成且驗證通過後才 Push 最終版本。

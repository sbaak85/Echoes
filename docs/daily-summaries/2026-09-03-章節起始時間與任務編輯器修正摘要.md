## 1. 章節起始時間設定

### 編輯器欄位

ChapterScriptEditor 的「黑畫面白色字幕事件」新增「章節起始時間」設定，只有觸發條件為「章節開始時」才會啟用。

可用模式：

1. `inherit`：延續上一章時間，不額外推進。
2. `elapsed`：設定距離上一章結束後經過幾小時；編輯器以 `0.25` 小時為調整單位，資料儲存為整數分鐘。
3. `clock`：直接指定下一個要到達的時刻；只會向未來推進，不會把遊戲時間倒退。

字幕事件資料新增：

- `chapterStartTimeMode`
- `chapterStartElapsedMinutes`
- `chapterStartClockMinuteOfDay`

ChapterScriptEditor 文件 schema version 更新為 `4`。舊資料沒有這些欄位時會正規化成 `inherit`，因此既有章節不會自行改變時間。

### 遊戲執行順序

第三章結束並銜接第四章時，正式順序為：

1. 保持既有全黑畫面。
2. 玩家完成自動或手動存檔。
3. 存檔成功後套用下一章設定的時間推進。
4. 同步結算生存狀態、營地電力與互動使用週期。
5. 在黑幕中播放下一章字幕。
6. 字幕結束後 FadeOut 黑幕，恢復遊戲畫面。

存檔內容會直接寫入推進後的 runtime snapshot；若寫檔失敗，遊戲中的時間與章節狀態都不會先行改變。成功後會標記 `chapterStartTimeAlreadyApplied`，避免同一個章節開場重複套用時間。

章節字幕仍維持純透明度 FadeIn／FadeOut，不加入向上位移、縮放或滑動效果。

## 2. QuestEditor 未完成 Objective 容錯

### 問題

新建主任務、Stage 與 Objective 後，如果 Objective 尚未完整設定便切換到其他任務，再回來點選該 Objective，舊流程可能在資料重新綁定的瞬間讀取 `Position = -1`，導致「索引 -1 沒有值」的未處理例外視窗反覆出現，使用者無法回到屬性面板修正資料。

### 修正

- Objective 表格改成共用單一 `BindingSource`，切換任務或 Stage 時先安全解除舊資料，再綁定目前 Stage 的 Objective 清單。
- 選取狀態尚未成立時不讀取 Objective，也不觸發資料警告。
- 未完成的 Objective 可以正常切換離開、重新選、點選並繼續編輯。
- 儲存時允許把未完成資料保留成草稿，不再跳出阻斷式確認視窗；錯誤會顯示在下方驗證清單及狀態列。
- 關閉 QuestEditor 前才統一執行驗證；若仍有錯誤，顯示一次可正常選擇「返回編輯」或「仍然關閉」的警告。
- 手動按下「驗證資料」仍可隨時更新驗證清單，不影響草稿編輯流程。

## 4. 後續接手注意事項

- 章節時間設定應掛在對應的 `chapterXX-Open` 章節開始字幕事件，不要另建平行的時間推進計時器。
- 新增其他章末存檔關卡時，要先建立下一章 runtime snapshot 並寫入 SaveData，寫檔成功後才提交到目前遊戲狀態。
- `clock` 模式代表「下一次到達指定時刻」，不是直接覆寫分鐘數；跨日必須向前推進。
- QuestEditor 的 Objective 清單應繼續共用 `_objectiveBinding`，不要恢復為切換時反覆建立、Dispose BindingSource 的做法。
- Objective 尚未完成不是編輯階段的例外；資料完整性提示集中在驗證清單與關閉前檢查。

# 回顧視窗模糊效能測試與暫緩套用備註

## 已確認決策

2026-09-05 使用者確認：「正式環境先不做出修改，先把這幾輪的測試結果與做法備註起來」。因此目前只保留測試、結果與備註，不將模糊預熱或靜態快照接入正式遊戲，不因候選方案存在就自行套用。

本決策針對本輪模糊效能實驗；不回退先前已完成的其他功能或素材預載入。實際遊戲測試中的素材預載入停用是瀏覽器攔截，並非正式程式變更。本次備註未重新跑測試、未修改 runtime、未提交或部署。

本摘要涉及 UI，後續工作適用 [專案 UI Skill](../../.codex/skills/browser-ui-focus-visuals/SKILL.md)。獨立繪製 fixture 僅量測渲染，不具完整遊戲輸入流程，不可當成控制權切換驗證。

## 兩輪方法與結果

| 環境與方法 | 樣本數 | 開啟繪製機會中位數 | 最大幀間隔中位數 |
|---|---:|---:|---:|
| 獨立測試頁，未預熱對照 | 5 | 46.1 ms | 100.6 ms |
| 獨立測試頁，動態模糊預熱 | 15 | 46.0 ms | 58.5 ms |
| 獨立測試頁，預先模糊快照 | 15 | 46.5 ms | 58.5 ms |
| 真實遊戲，停用額外預熱 | 5 | 47.8 ms | 25.1 ms |

共同使用五張背景：map_test01、map_test02、map_scene_06、map_scene_06B、map_scene_06C。Edge 152.0.4191.53，headless，1440 × 900，每次新瀏覽器程序；未清除 OS／GPU 驅動快取。

第一輪是合成 Canvas 背景、18 筆固定訊息。動態預熱提前以 opacity .01 繪製 blur(7px)，準備中位數 15.7 ms，另等待 500 ms，存在淡模糊與持續 GPU 成本。快照提前完成 Canvas 模糊、PNG 輸出及解碼，準備中位數 102.8 ms，另等待 500 ms，背景停在快照時刻。兩個候選每背景三次，對照每背景一次。

第二輪五次都重新啟動瀏覽器與真實遊戲，從未開過回顧的狀態推進到教學第二句，回顧有一筆真實腳本訊息。以測試瀏覽器攔截停用素材暖身模組，沒有模糊預熱。替換背景圖片內容，保持同一場景物件、鏡頭與任務，不是載入五個不同場景狀態。存檔請求隔離，無玩家存檔寫入。

第二輪依背景順序，首次繪製機會：46.3、49.7、44.7、47.8、48.3 ms；最大幀間隔：25.0、33.5、24.9、25.2、25.1 ms。

## 解讀限制

- rAF + 後置 task 為繪製機會代理指標，不是 GPU 完工或實體螢幕呈現時間，也不是純模糊運算耗時。
- 兩輪的背景渲染、訊息數、圖層、動畫及計時起點不同，不能用兩輪差值計算正式遊戲的預熱收益。
- 真實遊戲五次未重現獨立測試頁約 100 ms 的幀間隔，但仍有約 25–34 ms 間隔，不代表所有微頓已解決。
- 尚未以同一真實遊戲 fixture 比較三種方法，亦不能外推至長訊息列表、其他解析度、行動裝置或有視窗模式。若日後使用者要求繼續，應先補同條件比較再決定是否套用。

## 學到或沿用的技能

- 編輯器與遊戲共用場景 JSON；MapEditor 與 ChapterScriptEditor 的 C# 修改都必須重新建置、發佈並替換實際啟動 EXE。
- 重疊物件的輸入命中順序必須與繪製順序一致，並保留已選 Node 控制點作為最高優先的明確編輯目標。
- 章節腳本以可編輯資料區與自動生成 TypeScript 區分離，讓 GUI 可安全回寫而不覆蓋手寫管理器程式。
- ItemPoint 以「一點一種道具＋固定數量」作為第一版資料模型，生成狀態與一般場上掉落物分開管理。

## 重要設計決定

- `map_test01` 正式記錄為第三章場景，不作為序章或第一章開始場景。
- ItemPoint 生成週期包含：唯一一次、每日 06:00、每次進入場景；小地圖只標記啟用標記且仍存在的 ItemPoint 道具。
- ItemPoint 若被 Collision 阻擋，遊戲端尋找鄰近安全 NavMesh 位置；一般互動獎勵、丟棄物與 Debug 生成物不會因此自動成為小地圖標記。
- 右鍵圖層優先順序為 ItemPoint、強制引導線、劇情觸發區、互動區、Collision、NavMesh。
- 首句空白發話者表示旁白／無發話者；第二句以後空白才延續最近的具名發話者。

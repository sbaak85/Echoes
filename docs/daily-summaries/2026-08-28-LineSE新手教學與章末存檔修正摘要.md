## 5. 第三章章末手動存檔：真正根因與修正

### 重現根因

- Debug 任務快進指令會設定 `debugSaveIsolationRef.current = true`，用來阻止測試流程污染正式存檔。
- 章末選擇「自動儲存」原本可以繞過手動存檔限制，因此能順利進入第四章；但隔離旗標沒有清除。
- 後續任何一般手動存檔都會一直被判定為 Debug Scenario，形成以下現象：
  - 遊戲一開始手動存檔正常。
  - 章末呼叫存檔流程後，自動儲存可完成。
  - 進入第四章後再次手動存檔，`確認儲存` 永遠無法真正提交。

### 修正內容

- 章末明確開啟的手動儲存流程 `chapter04ManualSaveActiveRef` 優先於 Debug 隔離判斷，因此章末存檔確認框可以真正提交。
- `completeChapter04SaveCheckpoint()` 只有在玩家明確完成手動或自動儲存後，才解除 `debugSaveIsolationRef`。
- 成功切入第四章後，一般手動存檔恢復正常；不會在尚未存檔時提早解除保護。
- 章末 Option／存檔確認框同步修正：
  - 可在黑幕輸入鎖期間接收滑鼠、鍵盤、手把與虛擬游標操作。
  - 手把操作權由章末詢問框正確交接給 Options。
  - A 鍵依最後操作方式執行；虛擬游標未命中時，以目前選取按鈕作為安全目標。
  - `確認儲存` 直接提交明確的 `confirm` 動作，不再依賴延遲後可能已失效的焦點狀態。

### 實際流程驗證

- 已在 Debug 隔離狀態重現原本的阻擋。
- 修正後，章末手動 `確認儲存` 可成功。
- 進入第四章後，再開啟一般手動存檔仍可成功。

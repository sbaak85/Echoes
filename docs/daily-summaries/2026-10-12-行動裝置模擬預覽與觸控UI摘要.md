## 一、手機／平板模擬預覽視窗

### 位置與啟動

> ⚠ 預覽工具放在 `output/`（依 AGENTS.md 不提交），**不在 Git 裡**。換電腦時需依本節重建，或之後改放到受追蹤的工具資料夾。

| 檔案 | 用途 |
|---|---|
| `output/netlify-preview-server.mjs` | 靜態伺服器（port 3060），模擬 Netlify 以 `/` 提供 `output/netlify-site` |
| `output/device-preview/index.html` | 裝置外框預覽頁（手機／平板） |
| `output/device-preview/touch-shim.js` | 觸控裝置模擬腳本（只在預覽注入） |
| `output/device-preview/action-button.html` | 小地圖動作按鈕 4 款造型設計稿 |
| `output/device-preview/captures/minimap-geometry.png` | 從遊戲擷取的幾何小地圖（設計稿用） |

1. 建置靜態版（與 Netlify 相同）：

   ```bash
   pnpm exec vite build --config vite.pages.config.ts --base / --outDir ../output/netlify-site
   ```

2. 啟動伺服器：`.claude/launch.json` 的 `netlify-site-preview`（`node output/netlify-preview-server.mjs`）。
3. 開啟：
   - 手機：`http://127.0.0.1:3060/__device/?device=phone`
   - 平板：`http://127.0.0.1:3060/__device/?device=tablet`
   - 動作按鈕設計稿：`http://127.0.0.1:3060/__device/action-button.html`
4. 每次改完遊戲程式，重新建置後按預覽頁的「重新載入」即可。

### 伺服器的額外路由（只在預覽）

- `/__device/*`：提供 `output/device-preview/` 內的預覽頁。
- `/?touch=1&sw=寬&sh=高&fs=api|none`：回傳遊戲 `index.html` 時在 `<head>` 最前面注入 `touch-shim.js`。
- `POST /__device/capture/<name>.png`：把 data URL 存成 `device-preview/captures/<name>.png`（擷取遊戲畫面素材用）。

### 模擬了哪些「行動裝置狀態」

正式遊戲的行動版判定依賴觸控條件，電腦瀏覽器本身不成立，因此由 `touch-shim.js` 模擬：

| 項目 | 做法 |
|---|---|
| 媒體查詢 | `(hover: none)`、`(pointer: coarse)` 在 CSS 規則與 `matchMedia` 都改判為成立；`(hover: hover)`、`(pointer: fine)` 改判為不成立 |
| 觸控能力 | `navigator.maxTouchPoints = 5`、`window.ontouchstart` |
| 螢幕尺寸 | `screen.width/height/availWidth/availHeight` 依 `sw`/`sh` 偽裝，並隨直橫向互換（平板判定會用到螢幕短邊） |
| 滑鼠 → 觸控 | 真實滑鼠 Pointer 事件攔截後改發 `pointerType: "touch"`（沿用滑鼠 pointerId，`setPointerCapture` 才有效） |
| 無懸停 | 沒按住時的 pointermove／over／out 與 mouse hover 事件全部吞掉（觸控沒有 hover） |
| 右鍵 | 取消 contextmenu |
| 全螢幕 | 預覽面板內真正的全螢幕 API 不會回應，改為模擬：`fs=api` 時模擬成功進入全螢幕並通知外框收起網址列；`fs=none`（iPhone）移除 API，讓遊戲走自己的替代模式 |
| 手指位置指示器 | 白色圓環＋中心點跟隨滑鼠、按下變大變亮；只給測試者看，不參與遊戲輸入 |
| 按壓計時 | 回報按下時間、最大位移，並依遊戲規則（100ms／8px）標示「單點／長按／拖曳」 |

### 預覽外框功能（`index.html`）

- 裝置選單、**旋轉**（直／橫）、**模擬瀏覽器網址列**（依機型扣掉上方網址列／狀態列與下方工具列高度）、**重新載入**、**離開全螢幕**（模擬返回／下滑手勢）。
- 依面板大小自動縮放顯示；資訊列顯示方向、螢幕尺寸、遊戲視口尺寸與顯示縮放。
- 記住上次選的機型與方向（localStorage）。
- 兩個預覽同源，**共用同一份遊戲存檔**（瀏覽器 localStorage），不會動到 `SaveData/`。

### 模擬的限制

- 仍是電腦上的 Chrome：無法重現 Safari 專屬行為、瀏海安全區、實際像素密度與手指手感。
- 網址列高度為估計值；真機因瀏覽器版本與系統「顯示大小」設定，可用寬高會不同（例：S25 Ultra 在顯示放大時視口只有約 365px）。
- 按鍵盤會讓遊戲切回鍵盤輸入模式，測試時只用滑鼠。
- 內建瀏覽器面板隱藏或在背景分頁時，遊戲畫格與計時器會暫停或被節流，角色移動、時鐘排版等可能停住；需把分頁切到前景再觀察。
- 上線前仍要用實體手機與平板各實際操作一次。

## 三、觸控單擊／長按判定

- 範圍：只有畫面**下半部**的觸控會先等待判定；上半部與滑鼠操作不變。
- 規則（`app/movement-lab.tsx`）：
  - `TOUCH_TAP_MAX_MS = 100`：100ms 內放開且移動未達 8px → **單點**，在按下位置走一般點擊流程（移動或互動），顯示點擊特效。
  - 按住超過 100ms → **長按**，在按下位置轉成虛擬搖桿。
  - `TOUCH_DRAG_THRESHOLD_PX = 8`：100ms 內移動達 8px（8dp）→ **拖曳**，立即轉成搖桿並套用目前位移。
  - `pointercancel` 時取消，不把被取消的手勢補成單點。
- 參考：行動平台常見的單擊判定約 100～300ms、移動閾值約 8～10dp；真機若誤判可放寬到 150～200ms。

## 四、小地圖動作按鈕

- 用途：角色接觸可互動物件時，除了原本世界上的手型提示，也在小地圖外圈左上浮出按鈕，玩家不必把手指移到遠處即可觸發。
- 外觀：金色 1/6 環，頭尾漸層淡出，中央為遊戲手型（手拿箱子）圖示；琥珀色玻璃底＋金色外框。
- 尺寸（未縮放，整體再乘 `--ui-scale`）：

  | | 手機（小版） | 平板（大版） |
  |---|---|---|
  | 內圈線 | 小地圖外緣＋6 | 小地圖外緣＋6 |
  | 環厚 | 64 | 84 |
  | 扇形角度 | 72° | 82° |
  | 圖示 | 46 | 52 |

- 判定區：比外觀大一圈（內緣從小地圖邊緣起、外緣＋12、角度各＋6°）；`touch-action: none` 避免瀏覽器把微小移動當成捲動。
- 顯示條件：與手型提示的可點範圍同步（`syncMinimapActionButton`）；對話、阻擋型 UI 開啟或小地圖不可見時隱藏；只在行動版。
- 觸發：按下即觸發（`pointerdown`），呼叫與手型提示相同的 `mobileInteractionActionRef`；畫布 `pointerdown` 另有幾何判定作保險，確保優先於點擊地點與搖桿。
- 動畫：由小地圖中心往外推出並淡入，淡入 0.10 秒、位移 0.14 秒。
- 設計過程：先在 `action-button.html` 做 4 款（玻璃弧、能量光帶、暖金、雷達刻度），後收斂為暖金近版／外擴版，最後採暖金並分手機／平板大小。

## 五、平板判定與自適應

- 平板判定（`isTabletDevice`）：**螢幕短邊 ≥ 600 CSS px** 且符合 `(hover: none) and (pointer: coarse) and (min-width: 700px) and (min-height: 560px)`。結果寫入 `.game-shell[data-device-class]`，CSS 以此套用平板外觀。
  - 加入螢幕短邊條件，是為了避免手機在特殊顯示設定下被誤判為平板。
- UI 比例：手機 0.6；平板 0.6 × `TABLET_UI_SCALE_FACTOR`(1.12) = 0.672。網址 `?mobileUiScale=0.7` 可暫時覆蓋（0.3～1）。
- 生存／任務 UI 寬度（`--mobile-hud-mini-width`，由 JS 設定）：
  - 標準 200；平板在「兩塊放寬面板＋時鐘」放得進第一列時用 `TABLET_HUD_WIDE_WIDTH` 290。
  - 畫面太窄時自動縮窄讓時鐘留在第一列，最窄 `MOBILE_HUD_MIN_WIDTH` 170；時鐘寬度變化（字型載入）也會重算。
- 平板小地圖 176px（手機 132px）。
- 平板直向背包：量出 4 欄道具格實際寬度，以 `--inventory-fit-width` 讓視窗貼齊並置中。
- 背包裝備格：通用道具格的 `padding: 4%` 以整個背包圖區寬度計算，會把圖示擠出格子；改為裝備格固定 2px 內距、圖示填滿內容區。

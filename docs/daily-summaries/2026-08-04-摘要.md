# Echoes 每日摘要（2026-08-04）

## 完成事項

- 本段對話以確認任務系統缺口與規格為主，尚未開始修改遊戲程式。
- 確認「對話結束後自動派發任務」應由 `ChapterFlowManager` 負責。
- 確認任務進度應透過正式的拾取成功與互動成功事件接入 `QuestRuntimeManager`。

## 沿用的技能與架構

- 章節固定流程由 `ChapterFlowManager` 串接，不把固定開場流程分散到一般對話事件。
- 任務判定使用穩定 ID，不使用可重新命名的顯示名稱。
- Objective 只監聽目前任務的目前 Stage，避免其他階段提前累積進度。

## 重要設計決定

1. `ChapterFlowManager` 新增 `startQuest` 動作：
   - `第三章_Section 1` 對話結束後，自動承接 `QUEST_CH03_MAIN_001`。
   - 任務接受動畫播放後才歸還玩家操作權。
   - 開場被 SKIP 時仍須派發同一任務。
2. `QuestRuntimeManager` 接入兩種正式事件：
   - `ITEM_ACQUIRED`：成功拾取指定 Item ID 與數量時累積進度。
   - `INTERACTION_COMPLETED`：互動條件通過、對話與完成效果完整結束後才計入。
3. 道具取得進度採「Stage 啟動後成功拾取累計」：完成後即使使用或丟棄道具，進度也不倒退。
4. 事件需具備防重複識別，避免同一次點擊或互動重複計算；任務進度需納入 SAVE。
5. 新增「複合道具收集 Objective」：同一 Objective 可要求多個 Item ID 與各自數量，全部達標才完成。
6. 任務 UI：
   - 未完成目標顯示 `☐`，完成顯示 `☑`。
   - 依 Objective 的 `ShowProgress` 決定是否顯示 `[0/3]` 等數量進度。
   - Stage 切換時更新為當前階段的目標清單。

## 注意事項與已知問題

- 串接 `startQuest` 前，必須先確保 `QUEST_CH03_MAIN_001` 已存在於正式任務資料，避免新遊戲流程找不到任務 ID。
- 互動失敗、取消對話、僅點擊或尚未完整執行完成效果時，不得送出成功事件。
- QuestEditor 後續需讓 Objective 可指定 Item ID、Interaction ID，以及複合道具需求。

# 2026-08-18 地圖舞台解析度與 1536 場景遷移規格

## 1. 本日結論與實作狀態

- 本文件記錄 `Scene_3 / map_test01` 後續的遊戲舞台、Camera 響應規則，以及地圖由 `1254 × 1254` 遷移至 `1536 × 1536` 的處理方式。
- 本日先確認規格，尚未把遊戲舞台改成新尺寸，也尚未轉換地圖 JSON。
- 待使用者將 `Assets/map/map_test01.png` 換成新的 `1536 × 1536` 等比構圖圖片後，再執行正式遷移。

## 2. PC 與高解析度螢幕的遊戲舞台

- PC 版遊戲舞台的基準邏輯尺寸訂為 `1280 × 720`，固定維持 `16:9`。
- 瀏覽器縮放為 100% 且內容顯示區足夠時，完整顯示 `1280 × 720` 遊戲舞台。
- 瀏覽器工具列、頁籤列會占用實際內容高度；內容區不足時應等比縮小，不可裁掉遊戲舞台。
- 2K、4K 等更高解析度螢幕只將同一個 `1280 × 720` 邏輯畫面等比放大：
  - 2K `2560 × 1440`：理想倍率為 `2×`。
  - 4K `3840 × 2160`：理想倍率為 `3×`。
- 角色尺寸、移動速度、碰撞、NavMesh 與遊戲 UI 的邏輯座標不因輸出解析度改變。
- 不得拉伸成非等比例畫面。

## 3. 地圖與 Camera 的關係

- 完整場景地圖預定為 `1536 × 1536`，它是世界內容範圍，不是一次完整顯示的畫面尺寸。
- Camera 在地圖上顯示當前裝置所需的可視矩形，並隨角色移動。
- PC 基準 Camera 可視範圍為 `1280 × 720`。
- 相對於 `1536 × 1536` 地圖，PC Camera 可移動的總額外範圍為：
  - 水平：`1536 - 1280 = 256px`。
  - 垂直：`1536 - 720 = 816px`。
- Camera 必須遵守地圖邊界；地圖內容不可重複貼圖或被強制拉伸。

## 4. 手機直向與橫向響應

- 手機直向時，不把 `1280 × 720` 畫面壓扁成直向；Camera 改用裝置的直向長寬比例，只拍攝同一張地圖中的直向區域。
- 手機橫向時，Camera 依裝置實際長寬比例決定可視矩形。
- 目前方向是以邏輯高度 `720` 為共同基準，再依裝置比例計算可視寬度，例如：
  - `16:9` 橫向：約 `1280 × 720`。
  - `9:16` 直向：約 `405 × 720`。
  - `19.5:9` 橫向：約 `1560 × 720`。
- 裝置像素解析度負責輸出清晰度；裝置長寬比例才決定 Camera 能看見多少地圖。
- 手機 UI 需依直向／橫向重新排列，並納入瀏海、圓角與系統安全區；不能單純縮放 PC 版 UI。

## 5. 非 16:9 與超出地圖範圍的黑色遮蔽

- Camera 視窗可依非 `16:9` 裝置比例響應。
- 地圖有效內容範圍固定為 `1536 × 1536`。
- 若 Camera 某一方向需要顯示的範圍超過 `1536`，地圖範圍外一律以純黑畫面襯底。
- 不放大地圖來硬填滿、不拉伸、不鏡像，也不重複地圖邊緣。
- 若 Camera 位於地圖中央，超出量原則上可平均分配在兩側；靠近邊界時可依 Camera 實際位置只露出單側黑色區域。
- 遊戲 HUD 與操作 UI 仍顯示在最上層，不應被黑色世界背景遮掉。

## 6. MapEditor 圖片來源與遊戲匯出路徑

- MapEditor 預設模板與「開啟圖片」主要從 `Assets/map` 選擇原始地圖圖片。
- 直接開啟 `.scene.json` 時，MapEditor 會先找 JSON 同目錄或 `public/maps` 的圖片，找不到才回到 `Assets/map`。
- MapEditor 的「匯出遊戲」會：
  1. 將目前載入的圖片複製到 `public/maps`。
  2. 將場景 JSON 輸出到 `public/maps`。
- 瀏覽器遊戲實際載入的是 `public/maps/map_test01.png`，不會直接讀取 `Assets/map/map_test01.png`。
- 因此 `Assets/map` 是原始／編輯素材來源，`public/maps` 是遊戲執行時的正式載入來源。

## 7. 目前 Scene_3 的實際狀態

- `Assets/map/map_test01.png`：`1254 × 1254`。
- `public/maps/map_test01.png`：`1254 × 1254`。
- 兩份圖片目前 SHA-256 相同，內容完全一致。
- `public/maps/map_test01.scene.json`：
  - `sceneId = Scene_3`
  - `image.width = 1254`
  - `image.height = 1254`
  - `world.width = 1254`
  - `world.height = 1254`
- 現有 NavMesh、Collision、互動區、出生點及其他圖形資料都以 `1254 × 1254` 像素座標為基準。

## 8. 從 1254 遷移到 1536 的規則

- 新圖必須是現有構圖的等比例放大版；若重新構圖或移動場景內容，純座標縮放無法保證對齊，必須人工校正。
- 單次等比遷移倍率為：

```text
1536 ÷ 1254 = 1.2248803828
新座標 = 舊座標 × 1.2248803828
```

- 正式遷移必須同步處理：
  - `image.width / image.height`
  - `world.width / world.height`
  - 玩家出生點與面向以外的位置數值
  - NavMesh 所有 Node
  - Collision 多邊形、矩形、圓形中心與半徑
  - 互動多邊形、互動矩形、互動圓形與全部互動 Point
  - 劇情觸發多邊形
  - 移動引導線
  - 傳送 Point、Entry Point 與地圖出入口範圍
  - ItemPoint、場上道具、掉落位置與相關半徑
  - 其他所有以地圖像素記錄的位置、長寬、距離或半徑
- 任務 ID、Stage／OBJ ID、互動 ID、對話、道具需求、完成效果、次數限制與事件條件均不得改名或重建。
- 遷移前應保留原 JSON；遷移後要檢查所有座標均在 `0..1536` 範圍內。

## 9. 正式遷移完成條件

1. 使用者先替換 `Assets/map/map_test01.png` 為確認過的 `1536 × 1536` 圖片。
2. 將 `Scene_3` JSON 的全部像素座標依固定倍率轉換。
3. 將新圖片同步至 `public/maps/map_test01.png`。
4. 更新 `public/maps/map_test01.scene.json` 的圖片與世界尺寸。
5. 以 MapEditor 視覺檢查 NavMesh、Collision、互動區與所有 Point 是否仍對齊底圖。
6. 執行 MapEditor self-test 與 UI smoke test。
7. 執行遊戲相關測試與正式建置。
8. 在瀏覽器檢查 PC `1280 × 720`、高解析度等比放大、手機直向／橫向與地圖外黑色襯底。

## 10. 專案 UI Skill

- 後續只要修改或測試瀏覽器遊戲舞台、響應式 HUD、按鈕、選單、虛擬游標、鍵盤或手把操作，都必須先閱讀並套用 [browser-ui-focus-visuals](../../.codex/skills/browser-ui-focus-visuals/SKILL.md)。
- 必須隱藏瀏覽器原生焦點框／焦點底色，並讓含選單或可點擊按鈕的 UI 預設支援左搖桿循環選擇與 A 鍵觸發。
- 本次規格沒有刻意例外；正式實作時上述規則完整適用。

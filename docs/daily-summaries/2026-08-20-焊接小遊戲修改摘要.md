# 2026-08-20 焊接小遊戲修改摘要

## 摘要用途

本文件記錄「焊接各部位元件」第一階段小遊戲截至 2026-08-20 的實際程式狀態、已確認的操作原則、近期修正與後續驗證事項。

根目錄舊文件 [`製作摘要.md`](../../製作摘要.md) 保留早期設計討論，但其中「隨機正解、開場預覽、走錯路線立即失敗」已不是目前實作。後續維護應以本文件與現行程式為準，不可直接把舊版正解判斷恢復。

## 專案 UI 技能

本小遊戲屬於瀏覽器互動 UI，建立、修改、檢查或測試時必須套用專案技能：[`.codex/skills/browser-ui-focus-visuals/SKILL.md`](../../.codex/skills/browser-ui-focus-visuals/SKILL.md)。本次沒有刻意例外。

重點包括：隱藏瀏覽器原生焦點框、保留語意與可操作性、依最後輸入方式分配控制權，以及讓可點擊選單預設支援左搖桿導覽與 A 鍵啟動。

## 目前玩法大原則

### 1. 不判斷預設正確路線

- 目前不抽選 `activeRoute`，也不播放開場正解預覽。
- 畫面上的所有青藍色虛線圖邊都可焊接。
- 玩家可以在交錯與分岔處自由選路；焊線只根據玩家實際焊點行為記錄。
- 不因玩家走到所謂錯誤分支而立即失敗。
- 玩家抵達圖結構右側的任一有效終點時，即進入成功畫面。

### 2. 基礎路網

- 路網使用 441 × 320 的 SVG 遊戲座標。
- 五條來源路線會拆成交點、圖節點與可連通的 graph edges。
- 交叉但不相連、真正共用節點與可切換分支，由圖資料判斷，不能用自由手繪像素碰撞取代。
- 青藍色虛線路網全程保留，不會因焊接或候選線淡出而消失。

## 輸入方式

### PC 滑鼠與行動裝置

- PC 長按左鍵焊接；行動裝置長按觸控點視同左鍵。
- 焊槍視覺跟隨真實滑鼠／觸控位置，不把實體游標強制磁吸在線上。
- 真正的紅色焊線會投影並貼合附近的 graph edge。
- 放開後可移動到其他位置重新開始焊接，原本焊線保留。

### 手把

- 右搖桿移動科技焊槍游標。
- 靠近可焊線路後按住 RT 開始焊接；焊接期間焊槍與焊點會磁吸在線上。
- 分岔處只需大致把右搖桿推向目標方向，不要求精準描線。
- 放開 RT 後，游標可自由移動；再次靠近中斷處並按住 RT，可重新接續。
- 焊接期間隱藏一般虛擬游標，但不能影響滑鼠輸入模式。

## 紅色高熱焊線的現行規則

### 首段即時顯示

- 最小有效線段門檻為 `0.01` 遊戲座標單位，避免滑鼠慢移或手把首次位移被忽略。
- 不再使用預先生成的假起焊 Seed。
- 只描繪玩家真正走過的 graph segments。
- 高熱 SVG filter 使用 `filterUnits="userSpaceOnUse"` 與固定遊戲座標範圍；純水平首段不會再因包圍盒高度為 0 而延遲顯示。
- 焊線只保留原本的珊瑚紅／白熱核心與 Glow，不使用深紅色外緣。

### 單次按住焊接時的分支處理

- 玩家走向任何分支時，紅色焊線都會正常跟著描繪，不能因為不是預設答案而停在路口。
- 玩家折返並改走另一條線時，舊分支先保留。
- 新方向確認推進超過 `34` 單位後，已放棄分支才以 `720ms` FadeOut。
- 折返使用路徑歷程與 graph rejoin 判定；正常往前不能被誤判成回頭。
- 共用節點切換會在 junction 兩側分段補線，避免紅色焊線斷裂。

## 多次放開／重新起焊的候選線機制

每條獨立候選焊線都有：

- `trailId`
- 自己的 path samples 與 segments
- 最遠有效推進度
- 末端投影位置
- `pendingAbandonment`（預備棄線）
- `fading` 狀態

### 舊線續接

- 新一次起焊若距離既有候選線末端 `18` 單位內，會恢復該候選線的原始 path、進度與 `trailId`。
- 系統不會把這次操作誤建成第三條新線。
- 有效進度以保留路徑長度計算；折返與在同一段來回塗抹不能累積灌水。

### 領先與棄線規則

以 A、B 兩條候選線為例：

1. A 畫到 200 後放開，A 是目前領先線。
2. B 畫到 210 並首次超過 A：A 只標記為「預備棄線」，A、B 都繼續顯示。
3. 玩家回到 A 的末端續接，A 尚未重新超過 B 前，兩條線都保留。
4. A 的有效進度重新超過 B：代表玩家已明確改回 A，此時 B 才成為真正棄線並以 `720ms` FadeOut。
5. 共享的路段由各候選線自己的 segments 保護；淡出敗方時不能讓勝方仍使用的焊線一起消失。

這項規則不是「誰一超過就立刻刪掉另一條」，而是需要一次領先交換與預備棄線重新奪回領先，才確認淘汰現任領先線。

## 視覺與 UI

- 金屬板背景：`public/ui/welding/brushed-metal-background.webp`
- 科技焊槍：`public/ui/welding/Weldingtorch.png`
- 焊接期間顯示高熱焊點與 42 條循環火花。
- 真實焊線使用獨立前景 SVG layer，避免焊槍與焊點遮蔽首段。
- 焊線 Glow filter 覆蓋完整遊戲座標，不依賴單一線段的 object bounding box。
- 離開與完成按鈕保留遊戲自訂手把選取視覺，不顯示瀏覽器原生 focus 框。
- 成功後顯示「焊接完成」，玩家確認後才送出完成 callback。

## 遊戲與任務整合

### Debug

- `~` 指令列輸入 `Game 3` 可直接開啟焊接小遊戲。
- 每次開啟會增加 `weldingPuzzleSessionKey`，強制建立全新小遊戲 session。

### 正式互動與任務

- 正式互動 ID：`scene3-interaction-024`
- 任務：`QUEST_CH03_MAIN_006`
- 階段：`QUEST_CH03_MAIN_006_STAGE_02`
- 目標：`QUEST_CH03_MAIN_006_OBJ_04`
- 目標類型：`puzzleCompleted`
- 成功確認後會：
  1. 完成原互動流程。
  2. 送出 `puzzleCompleted`，`targetId` 為 `scene3-interaction-024`。
  3. 更新並儲存 Quest Save。

一般 `interactionSucceeded` 不會完成這個目標，必須由小遊戲成功事件完成。

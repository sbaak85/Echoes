## 沿用技能與設計決定

- 編輯器的下拉式參照清單在重建資料來源時，必須暫停事件回寫，避免 Windows 控制項自動選取第一項並覆寫正式資料。
- 任務 Objective 的排列順序與 Target ID 必須分開保存；上下移只改順序，不得重新指定目標。
- 編輯器正式 EXE 與原始碼一起保存，但 `bin`、`obj`、`publish`、`runtime` 與 TypeScript 編譯快取不納入 Git。
- 任務與劇情區的延遲各自獨立：劇情區延遲控制對話開始，任務延遲控制派發來源提出啟動後到正式啟動的等待時間。
- 劇情觸發區的任務狀態條件應明確使用 `questState`；需要前置任務完整結束時使用 `completed`，不可用下一個任務的 active 條件反向鎖住劇情區。
- 任務歷程只在沒有進行中任務時顯示，最多保留最近 3 筆；有進行中任務時仍維持原本任務標題、OBJ 與進度呈現。

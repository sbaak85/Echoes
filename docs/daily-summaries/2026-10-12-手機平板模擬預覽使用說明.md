# 手機／平板模擬預覽：使用說明與規則

## 用途與定位

- 在電腦上「依真實機型尺寸、模擬觸控條件」執行正式遊戲，用來檢查行動版 UI 與觸控操作。
- 預覽工具不是遊戲程式：遊戲的自動響應行為一律以 `app/` 內的程式為準，預覽只負責「讓電腦瀏覽器被遊戲當成手機／平板」。
- 本工具涉及 UI 檢查，修改與測試行動版 UI 時遵守 [專案 UI Skill](../../.codex/skills/browser-ui-focus-visuals/SKILL.md)。本文沒有刻意例外。
- 背景與完整規格見 [2026-10-12 行動裝置模擬預覽與觸控 UI 摘要](2026-10-12-行動裝置模擬預覽與觸控UI摘要.md)；本文是「每次要重新打開時」的操作手冊。

## 一、重新打開（最常用）

前提：本機的 `output/` 內已有預覽工具（見第三節檔案表）。關掉 Claude／瀏覽器視窗不會刪除這些檔案。

1. **請 Claude 開啟**：說「開手機／平板模擬預覽」。Claude 會用 `.claude/launch.json` 的 `netlify-site-preview` 啟動伺服器（port 3060），再開兩個分頁。
   - 若要自己啟動：在專案根目錄執行
     ```powershell
     & "C:\Users\sbaak\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" output/netlify-preview-server.mjs
     ```
2. **網址**
   - 手機：`http://127.0.0.1:3060/__device/?device=phone`
   - 平板：`http://127.0.0.1:3060/__device/?device=tablet`
3. **遊戲程式有改過時**，先重新建置靜態版，再按預覽頁的「重新載入」（見第二節）。

## 二、重新建置靜態版（遊戲程式改過後必做）

預覽跑的是 `output/netlify-site/` 這份靜態版（與 Netlify 部署同一種建置），不是 `localhost:3000` 的開發伺服器，所以改完 `app/` 不會自動反映。

**一定要在 PowerShell 執行**（專案根目錄）：

```powershell
& "C:\Users\sbaak\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" node_modules/vite/bin/vite.js build --config vite.pages.config.ts --base / --outDir ../output/netlify-site
```

- ⚠ **不要在 Git Bash 執行**：Git Bash 會把 `--base /` 自動改成 Windows 路徑，資源路徑變成 `/Git/assets/...`，遊戲整個白畫面。
- 建置完確認：`output/netlify-site/index.html` 內的腳本路徑應為 `/assets/index-xxxx.js`。
- 本機若有 `pnpm`，也可用 `pnpm exec vite build --config vite.pages.config.ts --base / --outDir ../output/netlify-site`（同樣在 PowerShell）。

## 三、檔案與用途

> ⚠ 依 AGENTS.md，`output/` 與 `.claude/` 都不提交，**不在 Git 裡**。換電腦時需依本文與 10-12 摘要重建。

| 檔案 | 用途 |
|---|---|
| `output/netlify-site/` | 遊戲靜態版（第二節建置產生） |
| `output/netlify-preview-server.mjs` | 預覽伺服器（port 3060）：以 `/` 提供靜態版；`/__device/*` 提供預覽頁；`/?touch=1` 時在遊戲 `<head>` 最前面注入 `touch-shim.js`；`POST /__device/capture/<name>.png` 存擷取圖 |
| `output/device-preview/index.html` | 裝置外框頁：機型選單、旋轉、模擬瀏覽器網址列、重新載入、離開全螢幕；依面板大小自動縮放；記住上次機型與方向 |

| `.claude/launch.json` | `netlify-site-preview` 啟動設定（Claude 用） |

## 四、模擬規則（`touch-shim.js`）

| 項目 | 規則 |
|---|---|
| 媒體查詢 | `(hover: none)`、`(pointer: coarse)`（含 `any-` 版本）在 CSS 規則與 `matchMedia` 都改判成立；`(hover: hover)`、`(pointer: fine)` 改判不成立 |
| 觸控能力 | `navigator.maxTouchPoints = 5`、`window.ontouchstart` 存在 |
| 螢幕尺寸 | `screen.width/height/availWidth/availHeight` 依網址的 `sw`／`sh`（直向尺寸）偽裝，並隨直橫向互換（平板判定會看螢幕短邊） |
| 滑鼠 → 觸控 | 真實滑鼠的 Pointer 事件攔下後改發 `pointerType: "touch"`（沿用滑鼠 pointerId，`setPointerCapture` 才有效） |
| 無懸停 | 沒按住時的移動、over／out、mouse hover 事件全部吞掉（觸控沒有 hover） |
| 右鍵 | 取消 contextmenu |
| 全螢幕 | `fs=api`：模擬成功進入／離開全螢幕並通知外框收起網址列；`fs=none`（iPhone）：移除全螢幕 API，讓遊戲走自己的替代模式 |
| 手指指示器 | 白色圓環跟隨滑鼠，按下變大變亮；只給測試者看，不參與遊戲輸入 |
| 按壓計時 | 左下角顯示按下時間與最大位移，依遊戲規則標示：**100ms 內放開且移動未達 8px＝單點**、**超過 100ms＝長按**、**100ms 內移動達 8px＝拖曳** |

遊戲頁網址格式：`/?touch=1&sw=<直向寬>&sh=<直向高>&fs=api|none`（外框頁會自動帶入）。

## 六、存檔規則（重要）

- 預覽中的遊戲進度存在**瀏覽器 localStorage**（靜態版沒有存檔伺服器），**不會動到 `SaveData/`**；手機與平板兩個預覽同源，共用同一份存檔。第一次開是新遊戲。
- 反之，用 `http://127.0.0.1:3000`（開發伺服器）測試時，存檔會寫進 `SaveData/`，與正式遊玩共用。**在開發伺服器開測試分頁一律加 `?noSave`**（例：`http://127.0.0.1:3000/?noSave`），只寫 sessionStorage，避免覆蓋存檔。

## 七、使用注意與限制

- 測試時只用滑鼠；按鍵盤會讓遊戲切回鍵盤輸入模式。
- 瀏覽器面板隱藏或分頁在背景時，遊戲畫格與計時器會暫停或節流（角色不動、時鐘排版停住）；觀察前先把分頁切到前景。
- 仍是電腦上的 Chrome：無法重現 Safari 專屬行為、瀏海安全區、實際像素密度與手指手感；網址列高度是估計值。
- 上線前仍要用實體手機與平板各實際操作一次。
- 10-12 摘要提到的小地圖動作按鈕設計稿（`output/device-preview/action-button.html` 與 `captures/`）屬設計過程稿件，本機目前未重建；需要時再補。

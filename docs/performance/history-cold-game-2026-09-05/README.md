# 回顧視窗：實際遊戲無預熱首次開啟測試

日期：2026-09-05。測試位置：目前 Echoes worktree，localhost:3000。只新增測試與量測資料，沒有套用模糊預熱或修改正式遊戲程式。

## 方法

- 每個背景各啟動一個全新的 Edge 程序及瀏覽器環境，重新載入遊戲，測一次首次開啟，隨後完全關閉該測試程序；共五次。
- Edge 152.0.4191.53，headless，1440 × 900。沒有宣稱清除作業系統或顯示驅動快取，也不是重新啟動電腦。
- 使用真實 React 遊戲、真實訊息回顧元件及既有動畫與模糊 CSS。固定背包教學第二句，回顧包含一筆實際腳本訊息。
- 測試瀏覽器攔截 ui-asset-warmup.ts，將素材暖身排程改為 no-op；各輪皆驗證攔截成功。沒有另外建立模糊圖層、快照或預先開啟回顧視窗。
- 以瀏覽器請求攔截替換 map_test01.png 的圖像內容，依序使用五張不同背景；保持相同場景物件、鏡頭、任務與訊息量，並非切換五個不同場景的完整遊戲狀態。原始圖片 SHA256 已保存。
- 每次載入等待 18 秒，確認第一句不顯示回顧入口，再推進第二句等待 1.5 秒後首次開啟。存檔請求隔離，沒有寫入玩家存檔。
- 在 rAF 中呼叫實際回顧按鈕 click，從呼叫前開始計時；觀察真實 overlay 插入 DOM，再以 rAF + setTimeout 記錄繪製機會時間。這是繪製機會代理指標，不是 GPU 完成、實體螢幕呈現時間，也不是模糊本身的純運算時間。
- 最大幀間隔為開啟後約 350 ms 的 rAF 採樣；不包含 18 秒遊戲啟動。各輪都驗證回顧一筆、無 pageerror，保存開啟後截圖。

| 測試 | 次數 | 開啟繪製機會中位數 | 最大幀間隔中位數 |
|---|---:|---:|---:|
| 本輪實際遊戲，完全停用額外預熱 | 5 | 47.8 | 25.1 |
| 前輪獨立測試頁，不預熱 | 5 | 46.1 | 100.6 |

前輪是合成 Canvas 背景、18 筆固定訊息和獨立模糊圖層；本輪是真實遊戲背景、一筆腳本訊息、原有圖層與動畫。計時起點也不同：本輪從實際元件按鈕啟動並等待 React 提交；前輪直接建立 DOM。因此此表只是並列觀察，不能用差值計算預熱的遊戲收益。

本輪沒有重現約 100 ms 的幀間隔。開啟仍有約 25–34 ms 的幀間隔，不能宣稱完全消除微頓，也不能證明其他訊息量、解析度或有視窗模式都相同。前輪預熱降低幀間隔的結果只能成立於該獨立測試頁，不能直接推論正式遊戲必須預熱。若要決定套用方案，應在本輪同一真實遊戲 fixture 內再比較兩種候選方案。

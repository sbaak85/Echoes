# 任務編輯器簡易使用教學

啟動檔案：`QuestEditor.exe`

任務資料儲存位置：`public/quests/quest-data.json`

## 基本操作順序

章節 → 任務 → 階段 → 目標 → 驗證 → 儲存

### 1. 建立章節

1. 在左側按【＋章節】。
2. 選取新增的章節。
3. 在右側設定：
   - `Chapter ID`
   - 章節名稱
   - 開場事件流程 ID
   - 結尾事件流程 ID
   - 下一章 ID

例如第三章可使用：

- Chapter ID：`CH03`
- 章節名稱：`存活的準備`

### 2. 建立任務

1. 在左側選取任務所屬章節。
2. 按【＋任務】。
3. 在右側設定任務 ID、名稱、說明、任務類型與派發方式。
4. 「啟動延遲（秒）」預設為 0；例如填入 1，代表派發來源提出啟動後，
   還要等待 1 秒才正式開始任務。此欄位不負責決定由哪個劇情區派發。
5. 若任務必須等其他任務完成才派發，在「前置任務 ID」右側按 `[…]`，
   直接勾選既有任務。可複選；全部勾選的任務都完成後才會開放派發。

任務 ID 不可重複，例如：

`QUEST_CH03_MAIN_001`

### 3. 建立任務階段

1. 在左側選取任務。
2. 在中間上方按【＋階段】。
3. 設定 Stage ID、階段名稱與完成方式。
4. 如需延後顯示這個階段，設定「啟動延遲（秒）」。計時會在上一階段的
   切換演出完成、正式進入此 Stage 後開始；等待期間不顯示 OBJ，也不接受事件。
5. 「完成延遲（秒）」會在階段內條件全部成立後開始計算。完成狀態會先保存，
   等待結束後才播放 NEXT／任務完成演出並切換下一 Stage。

完成方式：

- `All`：階段內全部目標完成才算完成。
- `Any`：任一目標完成就算完成。

### 4. 建立任務目標

1. 選取一個階段。
2. 在中間下方按【＋目標】。
3. 在右側選擇目標類型。
4. 從右下方的外部 ID 清單選取 Target ID。
5. 設定需求數量、是否顯示進度與 HintIcon。
6. 如需讓同一 Stage 內的 OBJ 分批出現，可設定「啟動延遲（秒）」。此秒數
   從所屬 Stage 正式啟動後開始計算，等待期間該 OBJ 不顯示且不接受判定。
7. 「完成延遲（秒）」會在 OBJ 條件成立後開始計算。完成紀錄會立即保存，
   但核取、完成 Tween 與完成事件會等到倒數結束才播放。
8. 如需在 OBJ 第一次完成時切換介面，可設定：
   - `完成後介面操作`：無、開啟或關閉。
   - `目標介面`：`Inventory`（背包）或 `Options`（選項）。

只有 OBJ 從未完成變成完成的當下會執行一次；未達條件或重複事件不會反覆切換介面。

#### 複合道具收集：全部達標／任選 N 種

1. 將「目標類型」設為「複合道具收集」，在「道具需求」集合加入可收集的 Item ID 與各自數量。
2. 「複合道具判定模式」預設為「全部道具達標」：集合中每一種都須達到指定數量；外層需求數量不會把它改成任選。
3. 若選「任選 N 種」，外層「需求數量」就是種類數 N。例如五種道具各 ×1、外層填 2，累計取得任意兩種即可完成。
4. 若某種道具設定 ×3，必須累計取得 3 個才算一種；重複取得同一種不會增加種類數。此模式沿用累計取得，不會在消耗道具後倒扣。
5. 任選模式的進度顯示為「已達標種類／N」；全部模式則顯示集合內數量的累計進度。

N 須介於 1 與集合內不同道具種類數之間。集合不要重複設定同一 Item ID；驗證資料或關閉視窗時會檢查，不會因為尚未編完就阻止選取 OBJ。

常用目標類型：

- `CollectItem`：累積拾取指定道具。
- `HaveItem`：目前背包持有指定道具。
- `InterfaceOpened`：玩家打開指定介面；背包使用 `Inventory`、選項使用 `Options`。
- `ItemUsed`：成功使用指定道具；使用失敗或計量已滿時不計入。
- `InteractionSucceeded`：成功操作指定互動區。
- `EnterArea`：踏入指定區域。
- `SceneTransferCompleted`（完成場景轉移）：跨場景轉移完成、玩家實際抵達後計數。
- `DialogueCompleted`：完成指定對話。
- `CustomProgress`：燃料、食物等自訂累積進度。

#### 完成場景轉移設定

1. 目標類型選「完成場景轉移」；「判定目標 ID」填目標場景，例如 `Scene_6`，也可從外部場景 ID 清單選取。
2. 「場景轉移」分類內的「來源場景 ID」及「來源出口 ID」為選填。兩者留空時接受任意來源；只填來源場景時接受該場景的任意出口。
3. 若指定來源出口，必須同時指定來源場景，避免不同場景的 `scene-exit-001` 混淆。選取出口欄位後，外部清單會只顯示該來源場景的出口。
4. 「需求數量」是成功抵達次數，填 `1` 即首次符合條件時核取。未啟用的 OBJ 不計數；啟用前曾經到訪不會補算。
5. 只在跨場景轉移完成後判定。碰觸出口、無效目的地、讀檔或同場景傳送 Point 不會核取。未填目標場景也不會接受任何判定。

第四章 `QUEST_CH04_MAIN_001_OBJ_13` 已設定：`chapter04-section-1` 播完啟用，從 `Scene_3` 的 `scene-exit-001` 抵達 `Scene_6` 後核取一次。

### 5. 檢查錯誤

按上方【驗證資料】。

下方會顯示錯誤與警告；雙擊其中一行，可以跳到發生問題的項目。

常見錯誤：

- ID 重複。
- Target ID 尚未指定。
- 外部 ID 不存在。
- 任務沒有階段。
- 階段沒有目標。
- 前置任務形成循環。

### 6. 儲存

按上方【儲存】，或按 `Ctrl+S`。

若資料仍有錯誤，編輯器會詢問是否保留為草稿。正式使用前建議先修正所有錯誤。

## 小提醒

- 任務資料只保存其他系統的 ID，不會複製道具或對話內容。
- 新增道具、互動區或對話後，可按【重新讀取外部 ID】更新下拉清單。
- `Quest ID`、`Stage ID`、`Objective ID` 建立後不要任意更名，以免存檔與其他系統失去對應。
